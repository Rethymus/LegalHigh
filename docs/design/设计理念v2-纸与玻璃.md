# 设计理念 v2 —「纸与玻璃」Paper × Glass（2026-08-29）

> 定位：对 v1（`视觉系统规范.md`，token/材质参数层）的**语义升级**。v1 解决了「参考 Apple」的可验证性；v2 解决「为什么这是法律产品而不是套壳」。本文档是 Agent 实施的完整规格。
> GitHub 调研注记（2026-08-29，gh API 实测）：shadcn-ui/ui 122,444★（可及性+组合式组件基线）、ant-design 99,255★（企业信任设计语言）、rsms/inter 19,846★（字体驱动设计）、vercel/geist-font 3,604★（mono=机器声音的标签语言）；GitHub 搜索「legal design ui」无严肃设计语言——**法律领域设计语言是空白**，本文档填充它。

## 一、批判：现在的 UI 为什么「AI 化」

1. **均质卡片网格**：feature-grid 四张等宽卡、每个页面同构双栏——任何 SaaS 套上都成立，说明**没有领域身份**。
2. **居中 hero + 蓝紫渐变**：生成式产品模板脸；「便民惠民」的公共性没有视觉表达。
3. **法条被渲染成普通卡片**：法律文本的庄重物质性（法典版式、条文编号、脚注）完全丢失。
4. **harness 藏在代码里**：检索→绑定→校验→留痕是产品最大差异点，UI 上却只字未见——信任没有可视化。

## 二、四学科 × Apple 的设计转译

| 学科 | 核心理念 | UI 转译（可实施） |
|---|---|---|
| **法学** | 法律的物质载体是**纸与印**：法典、公文、印章、批注。权威来自版式（条文编号体例「第五百八十五条」、双细线书眉、脚注）。 | 衬线宋体标题=法之声音；条文卡做成**法典页**（书眉双细线+衬线条号+脚注式来源）；印章=状态（朱砂印泥红只用于效力标记）；页边留白守文书比例。 |
| **心理学** | 认知负荷（Sweller）→渐进披露；信任=能力可验证（Mayer）→**透明即信任**；平静技术。 | 每页 kicker→标题→白话导语三级披露；证据链组件把 harness 摆在明面（可验证性）；动效只做 180-320ms 微反馈。 |
| **社会学** | 便民=公共服务语义（办事指南式「一看就懂」）；数字鸿沟→适老化是硬需求（调研报告 §1.3 画像 6）。 | 每个法律术语旁配白话导语（只解释系统行为，不解释法条内容——不编造）；**大字模式**全局开关（localStorage 持久）；对比度 AAA。 |
| **软件工程** | harness 是产品本体；两种「语言」并置：**衬线=人的法律语言，mono=机器的工程语言**。 | 所有可溯源对象（条号/时间戳/评分/编号）一律 mono；DocHeader meta 行、证据链计数、审计日志统一机器声音。「法与 AI 的碰撞」=宋体与等宽字体在同一版面上对话。 |
| **Apple** | Clarity / Deference / Depth；材质 deference：内容优先，UI 退后。 | v1 材质层全保留（玻璃=AI 的物质性）；新增 deference 规则：页面 DOM 第一元素永远是内容标题，导航在视觉权重上低于标题。 |

## 三、设计语言「纸与玻璃」

- **纸 = 法**：暖纸色画布、墨色文字、衬线标题、印章红、法典版式（双细线、脚注）。庄重、温暖、公共服务感。
- **玻璃 = AI**：v1 材质层（屏幕采样模糊+内高光）、accent 蓝、mono 数据、证据链。精密、透明、冷静。
- **色彩分工（硬规则）**：
  - `--seal`（朱砂印泥红）**只**用于：效力印章（草稿/已核验/已签发）、高风险徽章、 Harness 里的「人工」节点。禁止作装饰色。
  - `--accent`（蓝）**只**用于：检索/AI 交互、链接、焦点环。禁止大面积铺底。
  - 其余一切 surfaces 用纸色/墨色阶——v1 的 n-灰阶保留为「玻璃侧」，新增暖纸阶为「纸侧」。
- **双字体制（硬规则）**：标题/条号/引文=衬线（Songti/思源宋体）；UI 文字=PingFang sans；一切数据（条号引用、时间、计数、编号、URL）=mono。任何页面同时出现两体即语言成立。

## 五、组件规格（Agent D 实施）

1. **`DocHeader`**（页面头，替换所有 h1+导语）：
   ```
   [kicker mono]  LEGALHIGH · 引用式问答 · MODULE 01
   [serif 大标题] 让每句话都有出处
   [白话导语]    检索不到就明说……（只描述系统行为）
   [meta mono]   语料 1,647 条 · 快照 2026-08-29 · 方法 bm25 · —— （右则可放 <Stamp>）
   底部 --rule 双细线（1px double 或 3px 双线）
   ```
   Props: `kicker, title, lede, meta?: string[], stamp?: ReactNode`。
2. **`EvidenceChain`**（harness 可视化，Home 与产出页共用）：
   横向四节点：`采集 → 检索 → 引用绑定 → 核验 · 留痕`；每节点=衬线序号①②③④ + 名称 + mono 计数（如 1,647 条 / bm25 / citations n / append-only）；节点间 hairline 箭头（→ 或 CSS 线）。第五节点「人工」用 seal 红点标记（法学侧人类在环）。Props: `steps: {label, sub, tone?: "ink"|"seal"|"accent"}[]`。
3. **`CitationCard v2`**（同名同签名替换 components/CitationCard.tsx）：
   - 外观：`--paper-2` 纸面 + `--rule` 顶部书眉双细线 + 底部脚注细线；保留轻材质阴影（elev-1），去玻璃 blur（纸不透玻璃）。
   - 头行：衬线条号「第五百八十五条」+ 右侧 law_title（sans 小字）；次行 chapter（mono 小字）。
   - 正文：条文文本（`.cite-text`，行高 1.9 阅读优先）。
   - 脚注行（mono 12px，`--ink-3`）：`施行 2021-01-01 · {status} · 来源 {kind 中文} ↗`（链接）。
   - 可选 prop `highlight?: string` 不需要——保持 v1 签名兼容。
4. **`Stamp`**（印章状态，纯 CSS）：
   圆形 64px，2px 双环 border（外 2px 内 1px，间隔 2px），内文两行：mono 小字（LH·状态）+ 衬线两字（草稿/核验/签发）；`--seal` 色+`--seal-soft` 底；`transform: rotate(-8deg)`；draft 状态用 `--ink-3` 灰印。Props: `state: "draft"|"verified"|"issued"`。用于 Drafting 预览右上角、Review 记录头。
5. **`Masthead`**（Home 顶）：
   报头式：左=衬线大字「LegalHigh」+ mono 日期行；右侧**竖排**白话格言（writing-mode: vertical-rl，衬线，`--ink-2`）：「法为民所立 · 智为民所用」——竖排是中文法律文书的体例记忆，是「非 AI 模板」的最强信号。
6. **法典目录 `TocRow`**（Home 模块索引用）：
   行式索引（非卡片）：`第一编〔衬线〕 引用式问答 —— 一句话的出处〔sans 灰〕 →`，行间 hairline，hover 时行首出现 seal 红竖线。像翻法典目录。

## 六、页面改造清单（Agent E/F 实施）

- **Home（重构）**：Masthead → 宣言 hero（衬线大标题两行：「法律不该是少数人的特权」「我们把条文交还给每个人。」+ 白话导语 + CTA）→ **EvidenceChain（活数据：/api/health、/api/evals 实时计数）** → 法典目录索引（六模块 TocRow + 一句白话）→ 左右不对称区（左=问答快捷入口 textarea 一体化；右=数据底座 manifesto：三铁律+来源表前 3 行+「全部来源 →合规中心」）→ footer。删除 feature-grid。
- **App shell**：nav 加 mono 序号（01 问答 02 研究 03 分析…）；顶栏右侧按钮组=大字切换 + 主题切换；brand 改衬线。
- **各模块页**：h1+导语全部换 `DocHeader`（每页 kicker 编号：01 问答 / 02 研究 / 03 案件分析 / 04 合同审查 / 05 文书起草 / 06 合规中心 / 07 设计系统）；QA/Research 的结果区顶部挂 EvidenceChain（静态 step + 实际 counts）；Drafting 预览加 Stamp；Review 记录头加 Stamp（state=首个批注状态映射）。
- **QA/Research/CaseAnalysis 的引用卡**自动继承 CitationCard v2（同名替换）。

## 七、验收（主会话执行）

1. `npm run build` 通过；pytest 不受影响（39 绿）。
2. 浏览器明暗双模式逐页截图：新 Home、问答（含新引用卡）、案件分析、文书起草（含印章）。视觉判据：任一页截图中，宋体标题 / sans 正文 / mono 数据三体同屏；印章红只出现在效力/高险/人工节点；无 feature-grid 卡片网格残留。
3. 大字模式切换后 cite-text 行高与按钮字号可见变化并持久（reload 后保持）。
