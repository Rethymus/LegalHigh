# 文书排版规范（M6-T3）

> 事实来源：本文档描述的是 `server/app/docxgen.py` **实际实现并经断言测试锁定**的版式（pytest 断言字体/字号/页边距/横幅），非理想化设计稿。修订版式必须先改 `docxgen.py` 与测试，再回写本文——与金标「先加金标再改规则」同一纪律。
> 参照惯例：党政机关公文格式（GB/T 9704）的页边距与仿宋正文字体惯例；域外参照不计。

## 3. 结构要素（按文书类型）

通用：
- 状态横幅（**状态机驱动，非装饰**）：律师函 draft→「草稿 · 未经执业律师核验签发——不得以律所/律师名义对外发送（《律师法》第13条）」（红色）；verified/issued→绿色核验/签发横幅（含核验人与签发人）；其他文书 draft→黄色「草稿 · 供内部审阅，未经人工核验定稿」。
- 落款区：律所/律师/执业证号/日期（律师函）或答辩人/具状人/日期（诉讼类）。
- 免责尾注：`review/analyze` 输出的 disclaimer 原文。

类型差异：
- 律师函：致送行无缩进（para_noindent）；催告要求逐条编号（numbered）；法律依据逐条附现行有效状态与施行日期。
- 合同：甲乙方 party 块（含统一社会信用代码）、编号副标题。
- 起诉状/答辩状：party 块、此致 closing（含受诉法院）。
- 授权委托书：权限逐条编号；转委托限制声明。

## 4. 修订双轨（M7-T1）

- 审查记录导出（`GET /api/reviews/{rid}/docx`）：每条 AI 建议以 **w:ins 修订插入**写入，`w:author="LegalHigh AI"`，段落以书签 `LH_{finding_id}` 锚定。
- 回传解析（`POST /api/reviews/{rid}/docx-return`）：按「建议：标记位于修订层/普通层」判定 pending/accepted/rejected，经批注状态机流转（非法流转记 skipped）。

## 5. 测试锁定（修改版式的必经之门）

- `tests/test_review.py`、`test_drafting_templates.py`：DOCX 生成合法性（PK 头）与横幅水印存在。
- 版式参数（本表数值）如需调整：改 `docxgen.py` → 更新本文表格 → 生成实测 DOCX 抽取 XML 复核（方法见 `corpus_selfcheck` 同风格的核验脚本思路）。

## 6. 已知与后续

- Web 预览（`.doc-paper`）与 DOCX 导出**同源不同介质**：Web 行高 2.1 为阅读优化；DOCX 行距由 Word 默认/样式继承（未显式锁定）——如需与打印严格一致，后续在 docxgen 显式设置行距并回写本表。
- 落款处「日期：　年　月　日」空位供手签，属草稿语义的一部分，非占位遗漏。
