## 一、cat-xierluo/legal-skills（705★，双许可 MIT/CC-BY-NC）——法律 Skill 生态头部【强·当日核验】

执业律师（杨卫薪，技术类纠纷领域）维护的 60+ 技能仓库，R434 发现的 legal-skillhub（2303 目录）
与 Greater-China-Legal 之外真正的**头部实践仓库**——活跃度（2026-09-30 仍多技能更新）与工程化
程度（CHANGELOG 版本纪律、故障注入测试、双仓实测）均远超此前登记样本。

**三个可复用点**：

1. **legal-skill-evaluation（CC-BY-NC）——法律 Skill 分层质量评测方法论**【高价值】：
   三档模式（快速 NOT_VERIFIED / 标准=候选绑定+三份材料+六维度+最小修复单元 / 发布=加
   Harness 稳定性收据+回归双门槛），核心立场「不用单一总分掩盖红线」。**对本项目**：R460
   四问框架审阅的在线评测可直接借其「标准档」结构设计读数维度；skills/legalhigh 若外部分发，
   可按其发布档备齐证据（本项目 llm_eval 四重门+九门即等价物，方法论互证）。
2. **verification-gate（MIT）——「编译过≠功能可用」的分层验证门**：8 阶段（编译层 1-4→
   功能层 e2e+真机 5-6）、断言功能结果而非存在元素、bug 修复必须新增复现测试、套件悬挂=未
   通过、不采信生产者自报 PASS。**对本项目**：与既有 qa_shots strict（断言身份+afterText）/
   write-E2E 粘性检查/视觉验收三轮循环完全同哲学——方法论互证，无代码引入；其「不采信生
   产者自报」一条反哺本项目 pre-commit 与 CI 的分层（快门=编译层，探针=功能层）表述。
3. **yuandian-law-search（MIT）——「把问题问准、把材料选准」的检索中间层纪律**：轻量路径
   （能回答即完成、不为凑正反两面另发请求）、预算意识（调用消耗积分，授权范围内执行）、
   候选量≠报告篇幅。**对本项目**：/needs 与 research memo 的检索编排措辞可对齐其「不重复
   全案分析」原则；MCP 工具描述可吸收其预算/边界声明风格。

**分发判定更新**：legal-skillhub 不是唯一收录目标——legal-skills 仓库本身是技能型分发的
头部渠道（但 CC-BY-NC 技能与 MIT 技能分轨，收录标准待其 contribution 流程核验，gated on
业主「提交收录」指令）。

## 二、ayunis-core/ayunis-legal-mcp（90★，MIT，R434 后新增）——德国法向量检索 MCP【中·README】

PostgreSQL+pgvector+Ollama embeddings 的德国法语义检索（Store API + FastMCP + CLI + 爬虫 +
XML 解析五件套，gesetze-im-internet.de 官方源）。**判定**：向量栈与本项目确定性 BM25 哲学
冲突（R425 判定维持）；但其**「多法域模型：source/document 身份与跨法域检索」**的字段设计
与本项目 source_registry+law_versions 双轴同构——架构互证；五件套分层（数据导入/API/MCP/
CLI/爬虫）是「语料资产服务化」的完整形态参考，登记 S2-T3 PyPI 打包的结构参考（gated A2 之外
的独立价值）。
