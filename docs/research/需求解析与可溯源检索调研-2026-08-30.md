# 需求解析与可溯源检索 —— 深度调研与管线设计（2026-08-30）

> 目标：用户输入**抽象的、可能语序不当**的需求描述 → AI 分析理解 → 给出对应**法律条款**与**相关案例**，案例/条款可连通官方链接，可溯源、真实可靠。

## 一、问题定义：词汇鸿沟（Vocabulary Mismatch）

普通用户的描述是「生活语言」：「老板拖欠我三个月工资怎么办」「网购到假货能退吗」；法条与裁判文书是「专业语言」：「劳动报酬」「经营者提供商品或者服务有欺诈行为」。两者词汇几乎不重叠——这是信息检索领域的经典问题 **vocabulary mismatch**。

**逐源核实的证据**：
- **LeCaRD**（法律案例检索基准，清华团队，SIGIR 2021，MIT 许可，[GitHub myx666/LeCaRD](https://github.com/myx666/LeCaRD)）：107 个查询案例 / 10,700 候选案例，查询与候选**同为裁判文书中的事实叙述**（专业语言）。其基线对比显示 BM25 等词法方法明显弱于领域 BERT（在 6.63 亿刑事文书上预训练）——说明即便同为专业语言，词法鸿沟已显著；**生活语言→专业语言的鸿沟只会更大，且该基准未覆盖**（查询并非普通人口语）。
- **HyDE**（*Precise Zero-Shot Dense Retrieval without Relevance Labels*，Gao/Ma/Lin/Callan，2022，[arXiv:2212.10496](https://arxiv.org/abs/2212.10496)）：让 LLM 先生成「假设性答案文档」，再以其为检索枢纽。论文明确指出假设文档「捕捉相关性模式但可能含错误细节」——因此**证据必须由确定性检索器获取，生成物只作中间表达**。
- **本项目既有资产**（内部实证）：`server/app/research.py` 已实现 BM25 三组查询扩展（原句/关键词/编章扩展，PRF 风格），`qa.py` 已有 premise-check；`ai_governor.py` 已提供带三道 gate 的受控 LLM 通道。

## 二、管线设计：「薄 AI」双轨——AI 理解意图，确定性引擎取证

```
用户模糊输入
   │
   ▼
[A] 理解层（AI 可选，受控）── 仅做「改写与结构化」，不产出事实
   │   输出固定 schema：{understood 重述, issue_type, assumed_causes 案由假设,
   │                    keywords 检索词(3–8), cautions 注意事项}
   │   · 无 AI 配置 → 降级：deterministic 关键词抽取（research.extract_keywords）
   ▼
[B] 取证层（确定性引擎，无 AI，幻觉无法进入）
   │   keywords → corpus.search（BM25 多查询）→ citation_of 逐条校验
   │   keywords → cases.search（案例样本库，仅可公开查证案件）
   ▼
[C] 呈现层（可溯源）
   · 法条卡：官方原文 + 官方核对入口（flk.npc.gov.cn，语料 authority 字段）+ 快照原文链接
   · 案例卡：样本库案件 + 官方发布入口（最高法典型案例栏目/案例库/最高检发布厅）
   · 温度卡：12348 / 法律援助 / 找专业律师（Legal Safety §45 句式）
```

**关键原则（防幻觉三闸）**：
1. AI 只写「查询」，永远不写「证据」——法条与案例都来自本地语料/样本库的确定性检索；
2. LLM 输出必须过 JSON schema 校验，解析失败即降级为确定性关键词（不硬编码假设）；
3. 案由等一切「理解性判断」显式标注为**假设**，最终以用户补充事实与专业律师确认为准。

## 三、与既有能力的复用关系（不手搓）

| 能力 | 复用来源 | 本管线中的角色 |
|---|---|---|
| 受控 LLM 通道（BYO key + 三道 gate） | `ai_governor.chat`（OpenAI 协议插件层） | Stage A 理解层 |
| BM25 多查询检索 | `research.build_research_memo` 的查询合并逻辑 | Stage B 取证（法条） |
| 前提核查 | `qa.check_premise` | 对含错误前提的输入显式纠正 |
| 案例样本库 | `cases.search` | Stage B 取证（案例） |
| 官方链接 | 语料 `authority_pointer`（flk）+ `source_url`（快照）+ 官方发布入口 | Stage C 可溯源 |
| 温度组件 | WARM_TIPS | Stage C 求助指引 |

## 四、官方链接策略（不虚构 URL）

- 法条「官方核对入口」：**flk.npc.gov.cn**（国家法律法规数据库，corpus 每部法律的 authority 字段已带指引）——链接到官方库入口而非伪造条文深链（flk 深链为动态 JS，伪造即幻觉）。
- 法条「快照原文」：`source_url`（Wikisource 快照页，随语料构建已核验）。
- 案例「官方发布入口」：最高法典型案例栏目（court.gov.cn/zixun/gengduo/104_3.html，已核验）、人民法院案例库（rmfyalk.court.gov.cn）、最高检网上发布厅（spp.gov.cn）——**栏目级官方入口**；个案深链待 M6 案例库接入后补录。
- 域外判例：CourtListener 站内搜索深链（`/?q=案件名`，搜索链接非文档伪造）。
