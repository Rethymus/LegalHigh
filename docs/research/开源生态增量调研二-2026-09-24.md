# 开源生态增量调研（第二轮，2026-09-24）

## 调研范围

在 R326 五项新发现基础上，本轮定向检索六个新维度：法规变更监测、法条版本 diff、法条相似度/嵌入、法律文档生成、法律可访问性/普法、法律 AI 伦理。

## 新发现

### 1. shuji-bonji/houki-hub（日本法令 MCP，MIT，0★，今日更新）
- 日本法令/通达/行政解释的 MCP 服务器 + 共享库 + Skill 群
- 与本项目设计理念高度一致：「LLM から正確に引き、出典付きで示す」（从 LLM 正确提取并附来源）
- **可参考点**：Skill 群概念——将法律检索拆分为多个可组合的 MCP Skill（而非单一大工具）
- **判定**：本项目 MCP 六工具已覆盖同等功能面，不引入

### 2. capazme/mcp-legal-it（意大利法律 MCP，Apache-2.0，18★，今日更新）
- 200+ 工具：已验证法规、案例法检索、法律计算器
- 附 Claude 插件
- **可参考点**：200+ 工具的粒度设计（比本项目 6 工具更细）
- **判定**：工具粒度过细可能增加 LLM 选择负担；本项目 6 工具 + 参数化设计已平衡

### 3. kevanwee/sg-legal-corpus（新加坡法律语料，0★）
- "Singapore legal authority as one point-in-time corpus"——点时语料概念
- **可参考点**：point-in-time corpus 术语与本项目 temporal layer（R144 AS_OF_DATE）同构
- **判定**：设计已对齐

### 4. LimEulYoung/lawful-mcp（韩国判例/法规 MCP，1★）
- 韩国案例法、法规、判决 MCP 服务器
- **判定**：R326 已登记 Korean graphify-legal-wiki，同判定

### 5. sh-patterson/legiscan-mcp（美国 LegiScan API MCP，11★）
- 美国州级立法跟踪 API 的 MCP 封装
- **可参考点**：立法变更监测（legislation tracking）——本项目「语料时效 SOP」已有制度但无自动化监测工具
- **判定**：中国无 LegiScan 等开放立法监测 API，不适用

### 6. yoonmgyg/sc_trend_analysis（美国最高法院趋势分析，2★）
- 全栈应用分析美国最高法院趋势
- **可参考点**：法院趋势可视化
- **判定**：数据源不可得（中国裁判文书无公开趋势 API），不适用

## 负面发现（搜索零命中）

以下方向无相关开源仓库：
- 法条版本 diff / 比较工具
- 法条相似度/嵌入（statute embedding）
- 中文法律文档生成模板
- 中文法律可访问性/screen reader
- Plain language 法律简化工具
- 法律 AI 伦理/问责框架

这些空白确认了本项目的先创性位置——已有的 version_fulltext、citator、xrefs、文书模板引擎等都是在填这些空白。

## 结论

第二轮增量调研与 R326/R123 结论一致：**开源法律科技生态（尤其中文/东亚法系）的最新发展以 MCP 标准化为主流方向**，与本项目 MCP 六工具 + 引用不变量设计高度一致。无新增可直接引入的代码依赖。增量边际收益持续趋零。

**值得持续关注的方向**：houki-hub 的 Skill 群设计（如果 MCP 生态向 Skill 组合演进，可作为后续架构参考）。

**语料时效自动监测**（legiscan-mcp 启发）维持登记为外部依赖型（中国无开放立法变更 API）。
