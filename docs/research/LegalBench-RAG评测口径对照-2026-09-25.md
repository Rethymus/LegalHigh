# LegalBench-RAG 评测口径对照研究（2026-09-25）

> 来源：arXiv:2408.10343 摘要页（WebFetch 2026-09-25 核验，【中】——摘要级核验，公式细节未读全文）。
> 关联：AGENTS「关键参考」已登记该论文；本文件把其口径与本项目金标评测逐项对照，回答「是否有评测盲区」。

## 1. LegalBench-RAG 是什么

- 首个法律领域 RAG **检索环节** benchmark：把 LegalBench 查询回溯到原始语料位置，得到 **span 级人工标注** 的 query–answer 对（6,858 对，语料 7,900 万字符，法律专家全量标注）；提供轻量版 LegalBench-RAG-mini。
- 核心论点：RAG 检索应强调 **precision@k（精确率）而非 recall@k**——把无关文本送入 LLM 上下文本身就是危害（上下文成本、延迟、诱发遗忘/幻觉）；少量高精度片段优于大量掺杂噪声的片段。精确检索同时使「为最终用户生成引用（citations）」成为可能。

## 2. 与本项目评测口径的逐项对照

| 维度 | LegalBench-RAG | 本项目 | 结论 |
|---|---|---|---|
| 评测单元 | 标注 span（最小相关片段） | 条文（article，含子条号三元组 law_id/no/sub） | 本项目语料按「条」切分（民法条均数十至百余字），粒度天然接近「最小相关片段」；无需改切分 |
| 主指标 | precision@k（误检入上下文=危害） | hit@5（recall 口径：目标条文进前 5）+ rank-1 66.5% | **rank-1 即 precision 代理**；hit@5 是「引用候选池覆盖率」口径——两者并存且分工公示，无盲区 |
| 引用质量 | span 精确性/最小性 | 引用卡四要素完整率（law_status/effective_date/source_url/label=100%）+ gate2 引用绑定（生成文本逐句绑定） | 本项目把「引用质量」拆成元数据完整率与绑定核验两道确定性门，比 span 对齐更适合无人工标注的现实约束 |
| 多法同概念歧义 | （未涉及） | 21 条 miss@5 定性为「多法同概念合理近命中」（R311） | LegalBench-RAG 口径下这类 case 应计入 precision 损失还是任务歧义取决于标注——本项目不伪造金标歧义标注，维持「如实记录 miss 归因」口径 |
| 数据规模 | 6,858 对专家标注 | 541 组自建金标（词法鸿沟实录随行） | 规模差一个量级；本项目金标的价值在「真实口语问法 + 鸿沟 note」，是 LegalBench-RAG 不覆盖的中文口语维度 |

## 3. 结论与行动

1. **无评测盲区**：本项目 hit@5（recall）/ rank-1（precision 代理）/ 法律级 hit@5（引用精度分解，R327）/ 拒答率 / 引用实体完整率 五指标组合已覆盖 LegalBench-RAG 强调的 precision 维度；「条级切分」天然满足 span 最小性要求。
2. **不引入 span 级人工标注**：成本不可行且与决策 14「只公示数字、不虚构正确率」口径冲突；541 组金标继续按「金标先行、事件驱动扩容」制度增长。
3. **不自造 precision@k 新指标**：多法同概念歧义在无人工歧义标注时计算 precision@3 会把任务歧义误算成系统误差——违反「不编造」红线。当前 rank-1 已是该意图的确定性代理。
4. 本文件的对照结论供未来「语义检索再评估」（决策 13）时引用：若引入向量检索做 A/B，评测集应同时报 precision 侧（rank-1）与 recall 侧（hit@5），防止只优化 recall 的检索器把噪声送进引用卡列表。
