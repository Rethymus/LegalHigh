## 一、外部调研（2026-09-09 核验，证据等级按硬约束 1 标注）

### 1.1 法律 AI 开源对标——ChatLaw（北大，7.6k★，AGPL-3.0）【强】

来源：github.com/PKU-YuanGroup/ChatLaw。4 个模型版本（ChatLaw2-MoE 4×7B 为主力），多 agent 协作 + 知识图谱 + 93,000 份裁判文书训练的 Text2Vec 检索模型；报告 LawBench 超 GPT-4 约 7.7%。

**关键发现：它的 README 强调「生成完整法律咨询报告」，但通篇没有可验证的逐答引用链。** 这确认了本项目的生态位差异——不与端到端法律大模型比生成能力，而在「每条断言可回溯、审计留痕、人工 gate」的**引用工程**上建立不可替代性。同时它提示两个可借鉴方向：

- **Text2Vec 启示**：本项目词法鸿沟实录（金标扩容时 14 条首拟未命中）应持续积累，作为语义检索（embedding 重排双通道）再评估的数据底座——与决策 2/jieba 的「金标证明受限再引入」同一触发逻辑，不提前引入。
- **AGPL 警示**：对标项目用强 copyleft；本项目**未授予许可证**（业主终裁），未来若开放许可需单独立项（见决策 19）。

### 1.2 LLM 应用安全——OWASP Top 10 for LLM（2025 版）【强】

来源：genai.owasp.org/llm-top-10。逐项映射到本项目：

| OWASP 2025 | 项目现状 | 缺口/动作 |
|---|---|---|
| LLM01 提示注入 | gate1 红线词 + 诱导测试（R27 实证「包赢/胜诉率」拦截） | **缺注入模式化测试**：把「忽略之前指令/扮演律师」类注入样串纳入 llm_eval 抽样门固定题型 |
| LLM02 敏感信息泄露 | 数据本机 + PIPL 删除通道 + AI 默认关闭 | **出域提醒缺口**：用户把含个人信息的合同文本送远程模型时，无前端警示——补「AI 出域前个人信息提示」（确定性规则即可） |
| LLM03 供应链 | 依赖哈希锁 + pip-audit + npm audit（CI 第六门） | 加 SBOM 附件（CycloneDX，见 S1-T5） |
| LLM07 系统提示泄露 | 客户端自报 system 已降级 | 无缺口，保持 |
| LLM08 向量/嵌入弱点 | 无向量检索（确定性 BM25） | 结构性免疫；语义检索再评估时须同门评估 |
| LLM09 错误信息 | 三 gate + 引用绑定 + 无命中显式说未知 | 量化缺口——评测 2.0 把「拒答率/扣发率」从日志变为指标（S2-T2） |
| LLM10 无界消费 | 本机 BYO key，无配额 | **缺口**：补每会话调用上限 + 费用估算提示（本地确定性控制） |

### 1.3 可访问性——WCAG 2.2 新增 9 条成功标准【强】

来源：w3.org/WAI/standards-guidelines/wcag/new-in-22。对本项目 AA 级直接相关的：

- **2.4.11 焦点不被遮挡（AA）**：TopBar 是悬浮铬层、Dialog 常驻——键盘焦点被浮动层遮住的风险真实存在，需探针验证。
- **2.5.8 最小目标 24×24（AA）**：分段控件/开关/链式按钮密集，已做 44pt 触摸目标（移动端）但桌面端无 24px 断言。
- **3.2.6 一致性帮助（A）**：援助入口（12348 横幅等）跨页面相对次序固定——现设计天然满足，需断言钉住。
- **3.3.7 不重复输入（A）**：六步向导已带上下文带填；起草表单跨页复用字段待核查。
- （4.1.1 Parsing 已废弃，勿再投入。）

动作：S2 阶段把上述清单做成 `qa_a11y` 行为探针（复用 qa_motion 的 CDP 架构），并入 run_qa。

### 1.4 RAG 评测映射——RAGAS 指标体系【强】

来源：docs.ragas.io/concepts/metrics/available_metrics。本项目回答=命中文本卡片（确定性），可低成本落地其**确定性子集**：

| RAGAS 指标 | 本项目确定性等价物 | 现状 |
|---|---|---|
| Faithfulness | 引用绑定 gate（扣发即 0 交付） | 已有（机制），未量化为指标 |
| Exact Match / String Presence | 引用串存在于输出 | gate2 已断言 |
| Context Entities Recall | 命中卡片的条号/施行日期字段完整率 | 可从金标评测程序直接计算 |
| Context Precision/Recall | hit@5 / MRR（已有 106 组） | 已有 |
| **弃权率**（LawBench 单列指标，已核验） | 无命中显式说未知的比例 + 前提纠错率 | **日志有、指标无**——评测 2.0 核心增量 |

### 1.5 判例引用核验（负面历史检查的基础设施）【中——入口存在、详情未核实】

来源：CourtListener Citation Lookup API（courtlistener.com/api/citation-lookup/，本次实测返回 403，需注册令牌；Free Law Project 官方运营）。引用不变量承诺「判例引用附负面历史检查」，当前案例库仅 6 件精选（指导案例等，无负面历史字段）。**L3 联邦层接入时**以该 API 为候选实现（注册免费令牌后实测），国内侧按既定口径：官方类案检索顺位 + 人工抽查，不爬取。

### 1.6 桌面分发【中——文档正文未能核验】

桌面壳为 Electron 44 + electron-builder 26（本地 package.json 实证）。electron-updater 支持 GitHub Releases 作为更新源（electron.build 长期能力；官方文档站本次两次访问失败 404/ECONNRESET，**细节以实施时官方文档核验为准**——「未核实」标注）。签名（Windows Authenticode/EV、macOS 公证）涉及证书采购，须业主预算决策（决策 16）。

### 1.7 已核实的新事实：云端 CI 全绿

推送即触发 qa 六门（pytest 182 + build + 数据纪律 + WCAG + pip-audit + npm audit）与 Pages，2026-09-09 两条 run 全部 success【强，Actions 记录】。含义：①决策项 8 关闭；②「RC 转 正式版」的最大闸门（持续集成证据）已在自动积累。
