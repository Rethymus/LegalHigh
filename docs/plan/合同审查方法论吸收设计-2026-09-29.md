> 来源：R434 调研登记的 CSlawyer1985/contract-review-pro（273★，MIT，V4.0）方法论资产。
> 本文档是 B3 待办的**设计先行件**：对映其方法论到本项目 Risk Inspector 的既有结构，
> 逐项给出采纳形态、依赖与闸门。**结论先行：w:del 修订路由必须内容先行**——当前
> 含「删除」字样的两条建议（L3「删除或改写」二义、L4 条款内短语级删除）都不能整段删，

> （违反「假交互要么实现要么禁用」纪律）。本文档即其内容管线的设计蓝图。

## 二、四项吸收的设计（按可落地性排序）

### T1 立场声明（stance）——低成本高确定，第一批落地

**设计**：审查创建（`POST /api/reviews`）增加可选 `stance` 字段（枚举：
`party_a|party_b|neutral`，缺省 neutral），落库于 review 记录、透出审计与前端详情；
DOCX 导出头部加一行「审查立场：代表甲方/乙方/中立（使用者自选，非资格声明）」。

**边界**：v1 立场只做**记录与呈现**（提醒律师本审立场），不改变检查点触发——
立场驱动的规则差异（甲方关注违约金上限、乙方关注责任上限）属内容工程，入 T4 管线。
**闸门**：无内容风险；PIPL/审计零涉及；schema 向后兼容（可选字段）。

### T2 框架审阅四问——AI 提示层增强，随 AI 草稿一并落地

> **状态：R460（2026-10-01 前夜）已实现**——app/review_ai.py + POST /api/reviews/{rid}/ai-frame（API-first），四问纯函数判分（结构+条款引用真实性），15 项离线测试；在线四问评测待 10-03 配额窗口。

四问（义务单向性/退出权不对等/虚假前提/违约对称性）是语义判断，确定性实现不可行；
归属 `app/ai_governor.py` 的审查类提示层（AI 默认关闭，启用时四问作为结构化自检清单
要求模型逐问回答并附条款依据——输出仍过三道 gate）。
**闸门**：AI 提示层变更须过既有注入判分与金标评测（llm_eval 四重门）；无额度时仅登记。

### T3 w:del 修订路由——内容先行的工程蓝图（本文档核心）

**目标形态**（5 分类路由的本项目子集，先落 delete/replace 两类）：

```jsonc
// checkpoints[] 增加可选 revision 块（无此块 = 现行 comment 行为不变）
{
  "id": "L4-final-interpretation",
  "revision": {
    "action": "delete",            // delete | replace
    "target": "最终解释权归甲方所有",  // 条款内精确跨度（必须在条款文本中逐字存在）
    "replacement": null             // replace 时为代拟文本（须过内容管线）
  }
}
```

**导出**：`_add_tracked_delete(paragraph, target, author, date)`（w:del 包裹，与
_add_tracked_insert 对称）；书签区间内「w:del(target) + w:ins(建议)」同段渲染——
回传三态锚定仍以建议 w:ins 为准（w:del 是律师可一键接受的便利镜像，不构成第二状态源）。
**回传**：docx_return 现有三态判定不动；w:del 的接受/拒绝不单独驱动状态机（如实解析
可观测，套用仍锚定建议修订）。

**内容闸门（硬前置）**：
1. 每个 revision.target 必须「逐字存在于条款文本」——构建期程序化校验（同术语卡引用
   核验纪律），不满足即拒绝加载该检查点；
2. **replacement 文本属法律内容生产**：逐条走「审查点金标先行（决策 13）→ 内容入
   checkpoints → 测试钉住」管线，不整包翻译 contract-review-pro 的 124 模板（MIT 出处
   注明，逐条对齐受控语料后采纳）；
3. 首批候选（目标跨度确定性高的删除类）：L4「最终解释权」表述删除（target=该短语，
   需先在审查点内定义定位词面）；定金超 20% 的比例数字改写（target=原文比例串，
   replacement=「20%」——数字级替换的法律确定性最高）。

**工作量分解**（后续执行轮）：①docxgen/_add_tracked_delete + 渲染 ②构建期 target
存在性校验 ③docx_return 可观测解析 ④首批 3-5 个 revision 内容 + 金标 ⑤前端详情展示。
估计一轮可闭合（①②③纯工程，④⑤内容+展示）。

> **状态：首批已于 R440（2026-09-29）全量落地**——L3/F3/F4 三个修订、逐字不变式（发射期构造+防御复核）、
> 加载期 fail-closed 五类形状、w:del/w:ins 书签区间渲染、回传删除态三态观测（不驱动状态机）、
> 前端修订行；金标表 7 正 2 反钉住。注：②的「构建期校验」落地为**发射期逐字复核**（target
> 定位对象是用户合同条款文本，构建期无从校验——正则跨度在条款文本上取得即逐字，见 R440）。

### T4 风险点模板库扩容——长线内容工程

contract-review-pro 的 124 风险点/53 清单/18 标准条款是合同类型维度的资产；本项目
审查点为通用型。吸收路径：按合同类型（租赁/劳动/买卖先行——语料已备）逐类型
「金标判定表 → 检查点 → 测试」三件套滚动，与语料扩张同节奏；不设一次性大扩容目标。

## 三、决策与闸门对照

- 本设计不触碰：批注状态机语义、审计主体、PIPL 通道、AI 三道 gate。
- T1 可即时执行（无闸门）；T3 的①②③可在 T3-④ 内容就绪后同轮落地（避免死代码）；
  T2 随下一次 AI 额度窗口；T4 长线。
