# 开发计划 v7 —— 生态就绪路线图（2026-09-15）

> 前序：v6（R90 立项）可执行项已基本清偿（S4 四项 R91–R92、S5-T1/T2 R93、S6-T0/T1 R95、S6-T2 清单①② R97/R99、粉饰五项 R94；余 S5-T3/S6-T3 为闸门项）。
> 本轮定位（R114 立项）：**项目身份升级——从「单机工具」演进为「可被生态消费的数据与服务提供者」**。
> 哲学不变：引用绑定、宁缺毋假、AI 默认关闭、不预测裁判结果；新边界：对外输出面扩大时，输出纪律与红线随行。

## 二、v7 波次

### S1「开放数据」（旗舰：把已完成的双链核验语料变成生态公共品）

| 任务 | 内容 | 验收 |
|---|---|---|

| S2-T3 发布 | PyPI 可选包名 or 仓库内 `server/mcp_server.py` 入口 + README 使用节 | 第三方以一行配置接入实测 |

### 闸门与既有决策的关系

- **决策 19（许可证）成为 S1-T2/T3 硬前置**——数据发布前业主必须定许可证（推荐：法条文本=公有领域事实声明 + 整理成果 CC0/CC-BY；仓库代码许可另议）。
- 决策 5（部署暂缓）不变：MCP server 本地运行，不涉公网部署。
- 红线 1/7 不变：检索输出永远引用绑定；无爬取（lawtext/官方页面均为授权通道）。

## 三、风险

| 风险 | 缓解 |
|---|---|
| MCP 工具被用于生成法律意见 | 工具描述显式声明「检索工具，输出为法条原文+元数据，非法律意见」；不提供任何生成型工具 |
| 数据集被下游断章取义 | 数据卡强制携带「非法律意见+核验口径+版本日期」声明文件（MANIFEST） |
| 语料增长触发性能预算 | 沿用 gate6 修订制度（R45 先例） |

## 四、排期与闸门

- S1-T1/S2-T1/S3-T1：无外部依赖，下一执行批次即可开工。
- S1-T2/T3、S2-T3：**gated on 决策 19**（业主许可证结论）。
- S6-T3（2026-12）、FTS5 spike（2 万条）、9-22 二次核对：沿用既有排期，不冲突。
