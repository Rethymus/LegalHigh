# M4 任务分解 — 法律研究 · 报告生成 · 案件分析平台（2026-08-29）

> 目标：在现有原型（引用式问答 / 合同审查 / 文书起草 / 合规中心）之上，补齐「**基于来源的法律研究 → 研究报告生成 → 案件人像 / 行为模式 / 法律要件建模**」完整流程，全程**可追溯、可溯源**。本文件是设计基线：三个实施 agent（后端研究模块 / 后端案件分析模块 / 前端）各自按所属章节自包含执行。
> 分派策略：单进程顺序执行（速率限制下不并行），主会话负责集成与端到端视觉验证。

## 〇、总纪律（对所有 agent 生效，违反即返工）

1. **不编造**：一切对外输出的「依据」只能是 (a) 语料内条文——经 `app.corpus.get_corpus().citation_of(law_id, no)` 解析（不存在即抛错）；或 (b) 用户输入文本的具体片段（引用时给出 span 原文）。没有依据的内容要么不输出，要么显式标注「库内未找到依据 / 证据不足」。
2. **引用不变量**：所有分析结果的引用对象统一字段：`{kind: "statute"|"text_span"|"corpus_note", law_id?, article_no?, article_label?, law_title?, status?, effective_date?, source_url?, text?}`。statute 引用在模块构建/请求处理时逐条校验存在。
3. **心理分析红线**：本系统的「行为模式分析」是**文本模式识别 + 谈判策略参考**，输出页与报告必须固定附言：*非心理学诊断、非医学意见、不构成对任何自然人的品格评价；仅基于所提供文本的表层语言模式*。禁止使用「人格/心理障碍/精神疾病/智力」类表述。
4. **个人信息保护**：案件分析端点**无状态**（不写 SQLite、不落盘用户文本）；报告 DOCX 仅在用户显式请求下载时生成。分析对象仅限用户主动粘贴的文本。
5. **凭据**：源码/示例/测试中不得出现任何可用凭据字面量（仅环境变量）。
6. **工程约定**：Python 模块放 `server/app/`，utf-8，中文 docstring 说明数据纪律；新端点挂 `server/app/main.py`；测试放 `server/tests/`，运行 `cd server && .venv/Scripts/python -m pytest tests -q`，**不得破坏现有 19 项测试**；用 Write 工具写文件（Bash 写源码会被安全钩子拦截）；不要启动服务器/浏览器（主会话负责）。
7. 复用现有组件：检索用 `corpus.LawCorpus.search`（BM25）；DOCX 排版参照 `app/docxgen.py` 的字体/页边距约定（仿宋正文、黑体标题、A4、公文页边距）。

## 一、Agent A —— 法律研究模块（后端）

### 1. 新文件 `server/app/research.py`

函数 `build_research_memo(question: str, law_ids: list[str] | None = None, top_k: int = 12) -> dict`：

- **检索**：对 question 做 3 组查询（原句 / 去停用词关键词 / 从 top 命中条文的 chapter 标题扩展一次重查），合并去重（按 law_id+no，得分取 max），按得分排序取 top_k。law_ids 非空时只保留指定法律。
- **memo 结构**：
  ```json
  {
    "question": "...",
    "scope": {"law_ids": [...] | null, "top_k": 12},
    "issue_frame": {"restate": "...", "keywords": ["..."]},          // 程序化改写：原问题 + 提取的关键词（不加任何模型观点）
    "framework": [{"law_id","law_title","chapters": ["第X编 > 第Y章"], "hit_count": 3}],  // 命中条文的编章聚类
    "cards": [ <完整引用卡，字段同 qa.answer_cards> ],
    "gaps": ["问题涉及『XX』，但当前语料（7 部法规）未收录该领域条文，本 memo 不作推断"],  // 诚实缺口：当命中数<2 或全部得分低于阈值时输出
    "references": [ {引用对象，见总纪律2} ],                        // 与 cards 一一对应的溯源表
    "disclaimer": "...(复用 qa.DISCLAIMER)",
    "meta": {"method": "bm25-multiquery", "queries": [...], "corpus_size": 1647}
  }
  ```
- **停用词表**：模块内常量（的/吗/呢/什么/怎么/如何/请/问 等），确定性、可测试。

### 2. 报告生成 `server/app/research_report.py`

函数 `generate_research_docx(memo: dict) -> bytes`：

- 结构：标题「法律研究备忘录」→ 生成时间/语料快照（复用 `drafting._snapshot()` 的日期与 manifest 信息，只读快照字段）→ 一、问题界定 → 二、法律框架（framework 表）→ 三、相关条文（每条完整条文文本 + 版本/施行日期/来源 URL）→ 四、检索说明与缺口（gaps 如实列出）→ 附录：参考依据表（编号 | 类型 | 出处 | 链接）→ 免责声明。
- 排版沿用 docxgen 约定；页脚注明「LegalHigh 原型生成 · 内容不构成法律意见」。

### 3. 端点（加到 `server/app/main.py`）

- `POST /api/research/memo` body `{question, law_ids?, top_k?}` → memo JSON（422 校验非空）。
- `POST /api/research/report` body 同上 → DOCX `Response`（filename=research_memo_YYYYMMDD.docx；Content-Disposition attachment）。

### 4. 测试 `server/tests/test_research.py`

- memo 全部 cards 引用可经 corpus 解析且字段完整；
- 多查询合并不产生重复卡；
- 无关问题（如 "asdfgh"）→ `gaps` 非空且 `cards` 为空或 ≤2，gaps 文案含「未收录/不作推断」；
- 生成 DOCX 字节数 >5000，zip 魔数 PK，段落文本含「法律研究备忘录」与「参考依据」；
- 现有测试保持绿。

## 二、Agent B —— 案件分析模块（后端）

### 1. 新文件 `server/app/legalmodel.py`：请求权要件模型库

**模型库结构**（模块常量，启动时逐条 `citation_of` 校验）：

```python
CLAIM_TEMPLATES = {
  "loan_repayment": {   # 民间借贷还款请求权（金融借贷纠纷主线场景）
    "name": "民间借贷·返还借款请求权",
    "elements": [
      {"id":"E1","title":"借贷合意（借款合同成立）","citations":[("civl-2020",667),("civl-2020",668)],"probes":[r"借条",r"借款(合同|协议|协议书)",r"欠条",r"约定(向|由).{0,12}借款"]},
      {"id":"E2","title":"款项实际交付（自然人借款：提供借款时成立）","citations":[("civl-2020",679)],"probes":[r"转账",r"已?支付(借款|款项)",r"交付",r"汇款"]},
      {"id":"E3","title":"还款期限届满/催告","citations":[("civl-2020",675)],"probes":[r"(到期|期限届满|逾期)",r"催(告|收|款)"]},
      {"id":"E4","title":"利率合规性（不得违反国家规定；禁止高利放贷）","citations":[("civl-2020",680),("civl-2020",585)],"probes":[r"年利率",r"月息",r"日息",r"利息.{0,8}%"]},
      {"id":"E5","title":"诉讼时效（三年）","citations":[("civl-2020",188)],"probes":[r"(20\d\d)年"]},
    ]},
  "breach_damage": {"name":"违约责任·赔偿请求权","elements":[577,585 组合，probes 检测 违约/损失/违约金]},
  "consumer_fraud": {"name":"消费欺诈·惩罚性赔偿请求权","elements":[消保法55 为主，probes 检测 欺诈/虚假宣传/三倍]},
  "wage_claim": {"name":"劳动报酬·支付请求权","elements":[劳动合同法30 主，82 兜底，probes 检测 工资/劳动报酬/拖欠]},
}
```

函数 `analyze_claim(case_text: str, claim_id: str) -> dict`：对每个 element，用 probes（正则，大小写不敏感）在 case_text 中找命中片段；输出矩阵：
```json
{"claim":{"id","name"},"elements":[{"id","title","status":"supported"|"unverified","evidence_spans":[{"excerpt","start"}],"citations":[<完整引用卡>]}],
 "summary":{"supported":3,"unverified":2,"overall":"部分要件有文本支持，其余待补充证据"},
 "references":[...], "disclaimer":"要件匹配为关键词级文本提示，不构成法律意见…"}
```
`unverified` 的 element 必须保留（诚实缺口），status 判定只依据文本命中与否。

### 2. 新文件 `server/app/profiling.py`：当事人人像（结构化抽取）

从 case_text 确定性抽取：当事人列表（甲方/乙方/原告/被告/贷款人/借款人/申请人/被申请人/公司名后缀 等 role 词 + 邻近实体词）、每方：`{role, name_hint, mentions:[片段], behaviors:[{type:("主张"|"抗辩"|"承诺"|"违约行为"),excerpt}], timeline:[{date_hint, excerpt}]}`（日期正则 `20\d\d[-年/]\d{1,2}[-月/]\d{1,2}` 与「X月X日」）。全部字段必须带 excerpt（可溯源）；抽不到就空数组，不推测。

### 3. 新文件 `server/app/behavior.py`：沟通行为模式分析（非心理诊断）

指标库（每条=正则 probe + 解释模板 + 应对建议），首批 6 条：威胁/施压语言、升级倾向（多次催告/最后通牒）、时间压力设定、合作信号（协商/分期/和解）、情绪强度（感叹号密度、极端词）、承诺履行记录。输出：`{indicators:[{id,title,level:"high"|"medium"|"low"|"absent",spans:[excerpt],note,advice}], fixed_disclaimer:"非心理学诊断…", references:[text_span 引用]}`。level 依命中次数分档（次数阈值写常量，可测试）。

### 4. 编排 `server/app/case_analysis.py`

`analyze_case(case_text: str, title: str | None, claim_id: str) -> dict`：合并上述三者 + `{"profile":…,"behavior":…,"claim":…,"summary":程序化串联（各模块 summary 拼接，不加观点）,"references":合并去重,"disclaimer":合并}`。**无状态**：不写库。

### 5. 案件分析报告 `server/app/case_report.py`

`generate_case_docx(analysis: dict, title: str) -> bytes`：标题「案件分析报告（草稿）」→ 案件概述（title+日期）→ 一、当事人人像（表格：角色/线索/行为/时间线，每格附片段）→ 二、沟通行为模式分析（指标表 + 固定非诊断声明）→ 三、法律要件矩阵（要件/状态/证据片段/依据条文全文）→ 四、综合提示（程序化 summary）→ 附录：参考依据表（statute 引用带 URL + text_span 列表）→ 免责声明。红字横幅「分析草稿 · 非法律意见 · 不作心理诊断」。

### 6. 端点

- `POST /api/case/analyze` body `{title?, case_text, claim_id}` → analysis JSON（case_text≥30 字校验；claim_id 非法 422）。
- `POST /api/case/report` body 同上 → DOCX Response。

### 7. 测试 `server/tests/test_case_analysis.py`

- 每个 CLAIM_TEMPLATES 的 citations 启动校验（import 时即断言）；
- 构造含借条/转账/催告/年利率 24%/2024年 的借贷样例文本：E1-E4 supported、有 span、spans 文本确实存在于原文；

- profiling：抽取到 借款人/贷款人 角色与至少 1 条日期；无实体文本 → 空数组不推测；
