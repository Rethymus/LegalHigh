## 一、现状盘点（计划的事实起点）

**已完成**：M0 调研核验（1,647 条语料，快照可溯源）；M1–M3 四模块原型 + 金标评测（30 组，hit@5=0.933）；M4 研究与分析平台（39/39 测试）；UI v6（22 路由、材质系统、诚实数据层、3 处错误引用已修复并建立审计口径）。

**核心差距（v6 前端 ↔ server 能力未接通）**：v6 页面目前由 `model.ts` 演示数据驱动；server 已具备 corpus/qa/review/storage(批注+审计)/drafting/docxgen 全链路但无前端调用。**M5 的本质就是「接线」**——把演示数据替换为真实 API 数据，这一步完成后「合同审查 + 批注留痕」与「文书起草即交付」即达成目标要求的最小闭环。

**工程债**：测试必须经 `server/.venv` 运行（裸 Python 缺 rank_bm25），入口歧义需消除；前端无类型化 API 客户端；无 CI；金标集仅 30 组。

## 三、贯穿性工程原则（写进代码约束，不因里程碑失效）

1. **引用不变量**：输出对象必须携带 `citations[]`（law_id/title/article_no/status/effective_date/source_url）；后端缺引用 500，前端无引用不渲染断言。
2. **工作流而非聊天**：所有功能是固定管线 + 程序化 gate；LLM 仅作为 M6-T4 之后可选的受限环节，永远在引用绑定校验之后。
3. **人工核验 gate**：律师函 `draft→verified→issued` 状态机；批注单向流转；未核验必带水印。
4. **append-only 审计**：批注/签发/投诉/导出全量落 audit_log，可重放。
5. **证据先于数据**：任何新数据源必须先入 `docs/research/evidence/` 快照 → `build_corpus.py` → `export_laws.py`，禁止前端或提示词内手写法条/案例。
6. **诚实降级**：检索无命中说「未找到依据」；字段缺失显示「待核/待填写」；未接入数据源显示「规划接入」——宁缺毋假。
